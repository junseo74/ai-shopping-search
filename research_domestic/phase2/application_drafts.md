# API 신청·정책 문의 문안

제출하지 않은 검토용 초안이다. 실제 이름·연락처·사업자 정보·사이트 URL은 저장소에 기입하지 말고 공식 신청 화면에서 사용자가 직접 입력한다. 아래의 호출량은 신청용 제안이며 실제 트래픽 측정치나 승인된 한도가 아니다.

## 공통 서비스 개요

서비스명: ai-shopping-search

서비스 URL/앱 링크: **사용자 입력 필요**. 로컬 프로젝트 경로는 외부 서비스 URL로 제출하지 않는다. 공개 URL이 아직 없으면 개발 중임을 밝히고 검토용 화면 제출 가능 여부를 문의한다.

이용 주체/담당자/비공개 연락처: **사용자 입력 필요**.

이용 목적: 국내 상품의 이름, 판매가격, 원상품 URL을 이용해 사용자의 검색어에 맞는 상품을 비교·추천하는 서비스를 개발하고 있습니다. 판매자 계정의 상품 등록·변경, 주문·배송 처리, 고객정보 조회는 요청하지 않습니다. 도매 상품은 단가와 최소주문수량, 사업자 구매 제한을 함께 구분하려 합니다.

현재 시험 범위: 서버에서 공식 GET 요청 1회로 최대 3개 상품을 확인하는 독립 프로토타입입니다. 제품명·URL 원문과 응답 본문을 디스크에 저장하지 않으며, 진단 증거에는 해시·가격·관측 시각만 남깁니다. 운영 DB 적재와 공유 엔진 연동은 아직 하지 않았습니다.

초기 검토용 요청량 제안: 수동 시험 1회 최대 3건, 개발 단계 하루 최대 100회·순간 최대 1 RPS 이내를 희망합니다. **실제 수요와 제공자 허용 한도에 따라 사용자가 조정할 값이며 코드가 보장하는 일일 제한은 아닙니다.** 현재 프로토타입 자체는 실행당 1회 요청으로 제한합니다.

수익 모델: **사용자 확정 필요**. 광고·제휴 링크·유료 기능 도입 여부를 실제 계획에 맞춰 밝힙니다. 승인받지 않은 가격 이력 DB, 콘텐츠 재판매, 제3자 데이터 API 제공, AI 학습은 요청 범위에 자동 포함하지 않습니다.

보안: 키는 서버 환경변수/보안 저장소에 보관하고 브라우저에 제공하지 않습니다. 인증 헤더·키를 넣은 요청 URL·응답 원문을 로그에 남기지 않습니다. 차단·인증 실패·한도 초과에서는 요청을 중단합니다.

운영 갱신·저장: 구체 캐시 TTL과 삭제·갱신 주기는 제공자 정책 확인 후 정하려 합니다. 이번 프로토타입에는 영구 상품 DB 저장 기능이 없습니다. 장기 저장이나 가격 이력이 필요해지면 별도로 요청하겠습니다. 이용 중단·계약 종료 시 처리 조건도 안내 부탁드립니다.

## 예스24 기본 API 이용 목적 입력안

ai-shopping-search에서 사용자 검색어를 기준으로 도서 상품명·판매가·원상품 링크를 조회해 비교·추천하려 합니다. 출처와 예스24 상품 상세 링크를 표시하고 판매처를 명확히 구분하는 구성을 검토 중입니다. 서버에서만 API를 호출하고 필요한 범위의 일시 캐시만 사용하겠습니다. 전체 카탈로그 축적·재배포 없이 이용하려 하며, 가격·재고 갱신 주기의 구체 운영 기준을 안내받고 싶습니다.

Partner 한도가 필요한 경우만 별도로 서비스 URL/일일 요청량/피크 RPS/담당자 정보를 제출합니다. 기본 API 신청과 애드온 수익 서비스 가입은 별개입니다. 애드온은 사용자 검토 없이 신청하지 않습니다.

## 11번가 서비스 등록·권한 문의안

위 프로젝트에서 **ProductSearch 검색 API**를 이용하고자 합니다. 판매자 상품관리 API와 별개로 현재 신규 신청 가능한 회원 유형과 발급 절차를 확인 부탁드립니다. 검색용 키에 필요한 서비스 URL, 출발지 IP 등록, 증빙서류가 있는지도 안내 부탁드립니다. 상품명·가격·상세 URL을 검색 화면에 표시하는 용도이며, 일시 캐시 및 가격 갱신 기준, 영구 DB 보관의 별도 허용 여부를 확인하고 싶습니다.

## 도매꾹·도매매 목적 분류 문의안

자체 개발 중인 가격비교·추천 서비스에서 getItemList의 market=dome와 market=supply를 각각 이용하려 합니다. 상품 등록·발주·결제 없이 이름·가격·URL·최소주문수량·사업자 전용 여부를 소량 조회하는 목적입니다. 목적별 신청 가이드상 어떤 유형으로 신청해야 하며, Open 키 외에 Private 권한 신청이 필요한지 확인 부탁드립니다. 가격비교 노출·일시 캐시와 장기 상품 DB/가격 이력 저장 허용 범위는 각각 어떻게 다른지도 안내 부탁드립니다.

자사몰 판매나 통합 주문관리 플랫폼이라고 허위로 분류하지 않습니다. 회신을 받은 목적과 키 신청의 서비스 정보를 일치시킵니다.

## 오너클랜 판매사 API·데이터 사용권 문의안

공개 상품 API 명세의 allItems 검색, updatedAt, itemHistories를 검토했습니다. 외부 소비자 대상 상품 비교·추천 서비스가 판매사 API 이용 범위에 포함되는지, 별도 파트너 계약이나 비용이 필요한지 확인 부탁드립니다. 상품 URL의 공식 반환 필드나 승인된 생성 규칙, 공급가격과 fixedPrice/pricePolicy/openmarketSellable의 표시 기준, 품절·단종 반영 및 데이터 보관 조건도 안내 부탁드립니다. 현재 URL을 임의 조합하거나 GraphQL API를 무인증 호출하지 않았습니다.

## 쿠팡 파트너스 검토 준비안

실제 등록할 채널 URL·광고 게재 영역·대가성 표시 화면: **사용자 준비 필요**.

2025년 공식 가이드에 안내된 최종 승인 과정과 2026년 9월 개정 정책을 확인한 뒤 현행 계정 화면의 신청 조건을 따르겠습니다. 상품 검색 API를 가격비교·추천 화면에서 사용할 수 있는 범위, 현재 Search 한도, 응답 캐시·장기 가격 이력 허용 조건을 확인 부탁드립니다. 판매자 WING 키가 아닌 파트너스 API 권한을 요청하는 건입니다. 실적·승인 상태를 허위로 기재하지 않으며 인위적 구매를 만들지 않습니다.

## GS SHOP 제휴 API 제안안

ai-shopping-search의 사용자 검색·비교·추천 화면에서 GS SHOP 상품을 소개하고 원상품 페이지로 연결하는 제휴를 검토하고 싶습니다. 상품명·판매가·URL, 판매 가능 상태, 갱신시각 제공을 희망합니다. 전체 카탈로그 또는 협의된 상품 집합 중 어떤 범위가 가능한지, 키워드 검색·증분 피드 여부, 허용 요청량, 계약·비용·캐시 및 저장 조건을 안내 부탁드립니다. 회사소개와 서비스 검토 화면은 **사용자가 실제 자료로 작성**하겠습니다. 판매자 입점이나 주문 연동 계약을 데이터 공급 계약으로 오인하지 않겠습니다.

## 정책 대기 몰에 공통으로 확인할 질문

- 외부 검색서비스에 제공하는 **outbound** 상품 API/피드/RSS가 있습니까? 입점몰이 상품을 전송하는 **inbound** API와 구분해 안내 부탁드립니다.
- 이름·원화 판매가·상품 URL을 받을 수 있는지, 전체 몰/승인된 판매자/선정 상품 중 어느 범위인지 확인하고 싶습니다.
- 상업적 검색 노출, 일시 캐시, 장기 DB 및 가격 이력, 제3자 재배포, AI 학습의 허용 여부를 각각 알려주십시오.
- 가격·품절 갱신, 삭제 요청·계약 종료 시 파기, 출처·제휴 표시, 한도·비용·필수서류가 있다면 안내 부탁드립니다.

NS홈쇼핑·SSG 등 판매자 문서만 확인된 곳에는 전체 시장 수집을 요청 가능한지부터 묻습니다. 올리브영·컬리에는 수동 제휴 링크 발급 외 자동 상품 데이터 제공이 있는지 별도로 확인합니다. 에누리·다나와에는 EP 제출과 반대 방향인 DB 공급 사용권을 문의합니다. 링크프라이스에는 30개 몰의 실제 참여 목록과 상품 데이터 접근권·재사용 조건을 확인한 뒤 범위를 정합니다.
