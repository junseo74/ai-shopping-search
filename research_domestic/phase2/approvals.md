# 공식 API 승인 신청 준비

2026-11-08 기준. 아래 7개는 1차 `인증 대기` 몰과 정확히 일치한다. 신청 문안과 확인 항목을 준비했으며 실제 신청·계정 생성·결제는 하지 않았다. 개인·사업자 정보, 실제 서비스 URL, 요청량은 사용자가 기입해야 한다. 로그인 뒤에만 보이는 필수서류는 미확정으로 표시했다. 난이도는 개발 관점의 상대 평가이며 승인 가능성이나 처리기한을 보장하지 않는다.

## 공통 체크리스트

- [ ] 이용 주체(개인/개인사업자/법인)를 결정하고 본인 명의 계정 사용 권한을 확인한다.
- [ ] 실제 서비스명·접속 URL 또는 검토 화면, 담당자 정보를 공식 비공개 신청 양식에 입력한다. 이 저장소에는 신분증·통장·사업자 서류나 실명 연락처를 넣지 않는다.
- [ ] [신청 문안](application_drafts.md)의 제안 호출량·목적·수익 모델을 실제 운영 계획에 맞게 수정한다.
- [ ] 검색 결과 노출, 일시 캐시, 영구 DB, 가격 이력, 재배포, AI 학습 용도를 각각 확인한다. 한 가지 허용을 다른 용도에 확대하지 않는다.
- [ ] 현행 약관을 직접 읽고 사용자가 신청·동의·제출한다. 별도 비용이나 약정이 있으면 가입 전에 판단한다.
- [ ] 승인 회신/계약·허용 범위·갱신/삭제 조건을 비공개로 보관한다. 발급 키는 환경변수로만 전달한다.

## 예스24

신청 경로: [공식 사이트](https://developers.yes24.com/docs/apikey). 난이도: 낮음(기본 키) / 별도협의(장기 DB).

확인된 조건: 예스24 계정 로그인 / API 이용 목적 및 서비스 정보; 계정 정보 자동 연동 / 약관 동의.

필요 서류: Partner 상향도 사업자등록증 등 증빙서류 없음(공식 FAQ). 기본 키 발급 별도 첨부서류는 공개 문서에 없음.

준비 정보(실제 값은 사용자 입력): 서비스명/URL 또는 앱 링크 / 일일 호출량 및 피크 RPS(상향 시) / 담당자 연락처는 사용자가 비공개 양식에 기입.

- [ ] 사용자가 이용 주체 계정으로 로그인
- [ ] 실제 서비스 정보 입력 후 약관 검토·직접 신청
- [ ] 발급 키를 YES24_API_KEY 환경변수로 전달
- [ ] 최소 1회 검증 후 출처·원상품 링크 UI 검토

미확정 항목: 제공자 갱신정책의 구체 TTL / 영구 상품 DB·가격 이력 별도 허용 여부.

추가 근거: [yes24_faq](https://developers.yes24.com/support/faq).

## 11번가

신청 경로: [공식 사이트](https://openapi.11st.co.kr/openapi/OpenApiServiceRegister.tmall). 난이도: 중간(권한 및 로그인 양식 확인 필요).

확인된 조건: 11번가 로그인 필요: 신청 경로 직접 HTTP 200이나 로그인 요구 문서 / ProductSearch 공식 개발가이드와 판매자 API는 구분.

필요 서류: 검색 API 발급의 필수 첨부서류는 로그인 전 확인 불가. 사업자등록증·판매자 가입이 검색용 키에 필수라고 단정하지 않음.

준비 정보(실제 값은 사용자 입력): 서비스 URL/이용 목적 / 담당자 연락처 / 출발지 고정 IP(요구될 경우에만).

- [ ] 사용자가 공식 API 센터 로그인
- [ ] 서비스 등록·확인에서 ProductSearch 사용 목적과 신규 발급 조건 확인
- [ ] 담당자/서비스 정보를 실제 양식에 맞춰 기입하고 직접 제출
- [ ] 검색용 승인 키만 ELEVENST_API_KEY로 전달

미확정 항목: 현재 검색 API 신규 신청 가능 회원 유형 / 키 승인 및 IP 등록 필요 여부(검색 API 기준) / 캐시·저장·재배포 정책.

근거: 1차 공식 안내 + [2차 HTTP 문서 확인](new_document_checks.json). 비공개 필드를 추정하지 않음.

준비 정보(실제 값은 사용자 입력): 자체 프로그램/가격비교 서비스 설명 / 정확한 연동 서비스명 / 사용자 연락처 / 상품 범위·최소주문수량 표시 설계.

- [ ] 사용자가 도매꾹 이용 주체 계정 확인
- [ ] 기술지원에 가격비교 용도를 설명하고 유형·권한 확인
- [ ] 공식 gate에서 실제 연동 서비스 정보와 연락처로 키 신청
- [ ] 요구된 Private 권한만 신청하고 승인 결과 보관
- [ ] 키와 목적 승인 확인 후 DOMEGGOOK_API_KEY 주입 및 최소 검증

미확정 항목: 가격비교·추천 서비스가 어떤 이용 유형에 해당하는지 / 상품목록 진단과 실제 연동에 요구되는 Private 승인 범위 / 외부 검색 노출·도매 가격 보관·재배포 허용.

추가 근거: [dome_purpose](https://openapi.domeggook.com/ko/articles/API-신청-가이드-787a96cd), [dome_start](https://docs.channel.io/domeggook_api/ko/articles/OPEN-API-이용-방법-bd7265d8).

- [ ] 사용자가 API센터 로그인 후 판매사 연동 신청 절차 확인

- [ ] 필요 서류가 안내되면 사용자가 공식 채널에 직접 제출
- [ ] read-only 스키마와 실제 상품 URL 제공 범위 확보 후 구현

미확정 항목: 계정별 API 신청 및 비용·승인 조건 / 소비자 가격비교 용도 허용 / 상품 URL 제공 필드 또는 승인된 URL 규칙.

준비 정보(실제 값은 사용자 입력): 실제 채널 URL / 광고 게시 영역과 표시안 / 서비스 사용 목적 / 현행 화면에서 요구하는 증빙.

- [ ] 정상 활동 후 공식 최종 승인 심사/필요 보완 진행
- [ ] 최종 승인 이후 파트너스 API 키를 보안 저장소로 발급·관리
- [ ] 가격비교 검색·저장 용도를 공식 확인 후 수집기 추가

미확정 항목: 현행 최종 승인 기준·신청 양식 전체 / 키별 Search 권한·최신 한도 / 응답 저장/가공/장기 보관 조건.

## GS SHOP

확인된 조건: 제안요청→정책협의→범위확정→구현/테스트→오픈 절차.

필요 서류: 제휴 API 필수 첨부서류·심사 SLA는 공개 안내에 없음. 상품 판매 입점의 신용평가/정산 서류를 데이터 API 제휴의 필수로 단정하지 않음.

준비 정보(실제 값은 사용자 입력): 회사/서비스 소개(실제 값은 사용자 입력) / 서비스 URL 또는 검토용 화면 / 필요 필드와 예상 요청량 / 운영·보안·갱신·삭제 정책 제안.

- [ ] 사용자가 공식 제휴 API 경로에서 제안 접수 방법 확인
- [ ] 준비된 서비스 개요 및 데이터 요청 범위를 검토해 직접 제출
- [ ] 제공 범위·가격·저장 정책 협의
- [ ] 계약·호출권한 부여 후 문서 기반 1회 검증

미확정 항목: 신규 검색서비스 제휴 접수 가능 여부 / 상품 API 제공 범위·검색 방식·단가/과금 / 저장·가격 갱신·제3자 노출 권한.

근거: 1차 공식 안내 + [2차 HTTP 문서 확인](new_document_checks.json). 비공개 필드를 추정하지 않음.

## 알라딘 추가 절차

알라딘은 1차 RSS 성공으로 위 7개에 포함되지 않지만 TTB API 키는 별도로 필요하다. [공식 TTB](https://www.aladin.co.kr/ttb/wmain.aspx)에서 사용자가 회원가입·URL 등록·약관 동의·키 발급을 진행한다. 상업적 검색·장기 저장 범위는 아직 미확정이며 RSS 구독 허용을 API 데이터 라이선스로 해석하지 않는다. 키는 `ALADIN_TTB_KEY`로 주입한다.

## 우선 순서

1. 예스24 기본 키와 캐시형 검색부터 검토한다. FAQ상 일반 상업 모델은 가능하지만 영구 상품 DB는 별도 문제다. 애드온 가입은 기본 API 이용에 필수가 아니며 이번에 신청하지 않았다.
2. 11번가의 현재 신규 ProductSearch 발급 조건과 알라딘 TTB 사용권을 확인한다.
3. 도매꾹·도매매는 가격비교 목적 분류 회신부터 받는다. Open 키만 발급됐다고 자체 연동 전체가 승인됐다고 판단하지 않는다.
4. 오너클랜·쿠팡·GS SHOP은 용도 승인·범위·키/계약이 확보된 뒤 진행한다.
